The design study

Less searching. More knowing.

The problem. Appointment search often makes people translate between provider directories, availability calendars, and unclear next steps. Daywell explores a calmer flow that keeps clinician fit and appointment timing in the same view.

The goal. Help a patient decide with confidence, keep important context visible, and make every control understandable on a small screen or with a keyboard.

01 · My role

One focused prototype

Independent personal project. I set the visual direction, mapped the scheduling flow, wrote the interface content, and built the responsive HTML, CSS, and JavaScript prototype. Provider names, ratings, and availability are illustrative sample data.

02 · Design reasoning

Compare before committing

The provider list and time picker stay together on wide screens so patients can compare fit and availability without losing their place. On narrow screens the experience becomes a clear vertical sequence.

03 · Typography + color

Warm, steady, readable

DM Sans carries interface labels and supporting text; DM Serif Display adds a human editorial note to the case story. Warm paper, deep forest green, soft mint, and a restrained coral state color keep hierarchy clear.

04 · Components

Small set, clear states

Clinician rows, specialty filters, date choices, time buttons, selected states, and a confirmation status message use consistent spacing and explicit feedback. The booking action stays disabled until a time is selected.

05 · UX + accessibility

Make state visible

Native buttons and form controls support keyboard use. Filter and date choices expose pressed state, messages announce changes, focus has a strong outline, labels are explicit, and reduced-motion preferences are respected.

06 · Implementation

Progressive, responsive UI

Built as a self-contained HTML page with semantic landmarks, CSS Grid and Flexbox, a small vanilla JavaScript state model, and no external runtime dependency. The booking confirmation is a local prototype state; it does not transmit health information.
