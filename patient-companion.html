INDEPENDENT DESIGN STUDY

Care context, without the clutter.

Problem. A patient portal can scatter the most useful details across appointments, reminders, documents, and messages. This concept brings the next care action forward while preserving a calm overview.

Goal. Make the patient’s next step visible, keep everyday tasks lightweight, and make it easy to move between visits, plan, and care-team messages without losing context.

01 · Role + scope

Concept to responsive prototype

Personal project. I set the information hierarchy, visual system, interaction states, and responsive front end. Patient and care-team details are illustrative; this is not client work or a connected medical product.

02 · UX decisions

Lead with what’s next

The upcoming visit and today’s plan appear before secondary records. Navigation changes the workspace in place, while the overview keeps messages and documents close enough to find quickly.

03 · Type + palette

Structured, not clinical-cold

Manrope gives headings a compact product voice; DM Sans keeps dense labels readable. Ink navy anchors navigation, softened indigo marks actions, and cool paper surfaces separate content without heavy shadows.

04 · Components

Consistent care blocks

Visit summaries, task rows, progress meters, message threads, and document items share predictable spacing, direct labels, and state changes. Actions have local confirmation so the interface never implies a real message was sent.

05 · Responsive + accessible

Comfortable at every width

Sidebar navigation becomes a scrollable tab row on small screens; two-column summaries stack into one column. Controls use native semantics, visible focus, live status text, and reduced-motion support.

06 · Implementation

Small, inspectable front end

Semantic HTML, CSS Grid and Flexbox, and vanilla JavaScript power the self-contained page. Checklist progress is derived from checked controls; navigation and sample replies are local prototype states with no health data collection.
